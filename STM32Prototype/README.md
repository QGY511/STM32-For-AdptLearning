STM32G474 voltage-mode buck control — 600 kHz
============================================

This replaces the empty NUCLEO-G474RE CubeIDE skeleton with a complete register-level voltage-control path. The ADC triggers once per PWM period. While armed, every ADC result runs the PI and writes exactly one HRTIM duty preload. There is no loop decimation. The register transfer to the active compare happens at the following period boundary.

The implementation has been compiled and software-tested, and the startup path has been debugger-verified on a NUCLEO-G474RE (PLL at 168 MHz, HRTIM Timer A counting, ADC ISR executing from CCM with sleep-on-exit). It has **not been electrically validated** with a power stage. The supplied image starts ADC/PWM timing with both gate pins inactive. After bench verification, set `BUCK_AUTO_START=1` in `Inc/buck_config.h`, or write `g_buck_command=1` through the debugger without halting execution. Write `0` to stop. Faults latch until reset. The command flag is checked every sample; it is not an asynchronous hardware emergency stop.

**September 2026 update: ISR budget and the cycle-by-cycle switching score**

Symptom: with the estimator and the time-optimal response enabled, the PI and the load estimator ran normally but the time-optimal pulse never fired after the state-anchored switching score was introduced. Root cause: the score was evaluated in thread mode, and the every-cycle ISR (PI + estimator + optimal-idle bookkeeping) had grown to about 262 to 274 of the 280 CPU clocks per period including exception entry/exit (static count of the `Debug` disassembly, two independent counts). In that band the ISR tail-chains back to back, the main loop gets zero to a few clocks per period, `trig` is never written, and nothing faults. Above roughly 296 clocks the same growth trips `BUCK_FAULT_DEADLINE`.

The control path was restructured so that the PI, the estimator and the switching score all run **every switching cycle inside the ISR**, and only the Ton/Toff solve and the adaptive gain update run once per transient in thread mode (the solve has since moved into the ISR as well: see the second update below):

- **Switching score in the ISR, integer only.** `S = (z_v/V_a)^2 + (d_iL/I_a)^2 + 2 rho (z_v/V_a)(d_iL/I_a) > 1` is evaluated as `u^2 + w^2 > 2^28` with `u = n_v + rho n_i`, `w = sqrt(1-rho^2) n_i` (Q14, five SMULL/SMLAL, one 64-bit compare, ~18 clocks; `buck_sa_trigger_i`). `g_buck_sa_va`, `g_buck_sa_ia`, `g_buck_sa_rho` stay float and live-tunable: the thread converts them into four integer coefficients whenever they change, into a double buffer published by a single pointer store (`g_buck_opt.sa_cur`), so the ISR never reads a half-written set. `Tests/test_optimal.c` checks the integer decision against the float score on 28.6 million points.
- **Estimator coefficients from a table.** The four Pade coefficients depend only on the active on-time, so `buck_est_lut_init()` (single precision, at start-up) fills a 449-entry table in 8-tick bins and the ISR replaces two reciprocal series and four rescales with one index and two `LDRD` (~40 instead of ~85 clocks). Table quantisation is 0.75 ns of on-time, about 11 mA of peak current, below the feedback-noise floor; the host oracle test error is unchanged (28 mA worst case). Cost: 7.2 KB of SRAM.
- **Cold state machine out of line.** OPT_WAIT/PULSE/SETTLE, arming and the soft-start ramp moved to `noinline, cold` helpers in CCM (`opt_cold`, `control_transition`, `reference_step`). The every-cycle path makes no calls. Those helpers do their HRTIM preload writes immediately after the deadline check, in the same guarded window as the normal compare write, PER before CMP1.
- **Handoff invariant** (historical; superseded by the ISR-side solve below): OPT_IDLE implied `req == 0 && ready == 0`, the only exit from OPT_WAIT was the thread's `ready`, and disabling `g_buck_optimal_en` mid-solve discarded the result instead of racing it.
- **Stretched-period floor.** `BUCK_OPT_PER_MIN_TICKS` (one normal period) extends Toff so the stretched period can never end before the ISR that restores the normal PWM, which runs at a fixed point about 4.5 to 5.3 thousand ticks into it. Only binds when the learned gain shrinks Toff/k.
- **Edge trigger, step-up only, short hold-off.** The trigger fires on the crossing OUT of the ellipse on the droop side (z_v < 0) and only after the state has been inside for `BUCK_OPT_ARM_CYCLES` (32) consecutive cycles; a residual droop left by a pulse cannot re-trigger, and a load step-down overshoot is ignored (the solver is a step-up algorithm and rejects it anyway). `BUCK_OPT_COOLDOWN` is now 6 cycles (10 µs, just covering the pulse-end scoring window); `BUCK_OPT_COOLDOWN_START` (2000) masks only arming and the end of soft-start. The earlier level-based trigger with a 3.3 ms cooldown phase-locked to the cooldown instead of the load: on the bench it fired ~1.1 ms after each load-on edge every third load cycle, on the PI's recovery tail, and a 10 µs cooldown with the level trigger produced a 258-pulse burst per step in simulation. Closed-loop simulation of the edge trigger: one pulse per step-up, none on step-down, 4 to 8 µs from step to pulse.
- **Telemetry.** `g_buck_status.thread_loops` is a main-loop heartbeat (frozen while `state == 1` means the thread is starved); `g_buck_status.opt_wait_cycles` was the number of switching cycles the last request waited for the thread solve (now always 1, the solve cycle); `g_buck_opt.trig` is now ISR telemetry (1 from the trigger until the pulse ends); `opt_score` remains the float display score computed by the thread from the ISR's last published `sa_zv`/`sa_diL`.
- The `__DSB()` after the compare write is now diagnostics-only; the estimator's `dv` reference is re-seeded when the stretched pulse ends so the first estimated cycle sees one period of `dv` instead of the whole pulse.

**September 2026 update 5: the time-optimal layer reworked on the current-mode loop (trigger, timing correction, equilibrium correction), after the bench fed it zero-count samples**

What the panel showed (two captures two minutes apart): `opt_trig_count` 293 547 → 640 240 with `opt_count` following, so the trigger fired at every cycle its mask allowed; the voltage captured at the trigger read 0 to 6 counts and `opt_verr` read 1000 counts (the ADC returning zero at the post-pulse sample as well); γ_on = γ_off = 2.0 and b = −3 A, all at their bounds. The scope capture, taken earlier, showed +500 mV spikes at ~4 ms intervals in the middle of the 3 A plateaus, not at the load edges: each is the voltage PI driving its 10 A current limit for a few periods on a zero sample, with a pulse fired on the same sample (the D4 marker). The real 1→3 A steps were handled by the current-mode PI alone with a ~30 mV dip, under the 80 mV trigger level set on the panel. The likely cause is the A0 sense connection (it was rewired for the current sense on A1); the firmware's part is that nothing in it could refuse a sample, a trigger or a residual, so a dead sample fired a pulse on garbage every 192 cycles and the clip-only learners integrated the garbage to their bounds. Bench check before anything else: `g_buck.status.adc_raw` must read ~1000 and `g_buck.status.adc_glitch` must not count.

The layer was rebuilt around what average current mode makes available (the inductor current is measured, so the terminal state of a pulse is *observed*, not inferred):

- **Trigger on the output-capacitor state.** `S = (z_v/V_a)² + (d_v/dV_a)² + 2ρ(..)(..) > 1` with `d_v` the one-period change of the voltage sample (counts): `C dv/dt` is the capacitor current, i.e. the load step itself before the current loop has moved the inductor (1 A = 8 counts per period). The old current-displacement axis reported what the current loop was doing, not the load. The score is computed only for a sample below `V_ref` and not rising (`z_v < 0`, `d_v ≤ 0`), which is also the only signature the step-up solver can act on; `g_buck_sa_dv` (default 16 counts/period, 2 A of capacitor current) replaces `g_buck_sa_ia`. A fast 3 A step fires in its first period (2.4 µs in simulation); a 20 to 40 µs slew fires on the level, two thirds of the way down the dip. Simulation with ±6 counts of ADC noise on both samples stays clean, ±8 false-triggers on the slope axis: `opt_score` now shows the score of the last candidate sample (below the reference and falling), so read it at steady state and raise `g_buck_sa_dv` if it sits above ~0.5.
- **Sample validity** (`BUCK_ADC_JUMP_COUNTS` 256): a feedback sample that differs from the last accepted one by more than 200 mV in one period (30 A of capacitor current) is held off for that cycle: the PI, the load estimate and the trigger use the previous sample; two consecutive such samples are accepted (a real collapse); the cycles right after the pulse are exempt. `g_buck.status.adc_glitch` counts them. ~7 clocks before the compare write.
- **Feedback-lost guard** (thread, `BUCK_SENSE_GUARD_US` 500): with the loop running and the reference above 200 counts, a sample below a quarter of the reference for 500 µs latches fault 6 (`BUCK_FAULT_SENSE`, outputs off). An open A0 would otherwise be regulated to the 10 A current limit.
- **One record per transient**, double-buffered (`g_buck.opt.rec[2]`): the ISR fills it as the state machine advances (trigger → solve → write → pulse → settle → settled) and hands it to the thread once, when the 192-cycle linear-controller transition ends. No live ISR→thread fields, one thread event per pulse, and a thread stalled for a whole transition still reads a consistent set. The residual window and the `OPT_MEASURE` state are gone; a rejected solve now returns to the PI from the (cold) write cycle, so the late-entered cycle after every solve never runs the hot path.
- **Timing correction on the measured terminal state.** `z_i,f = (i_s − RISE) − (I_eq − h)`: the sample current at the first post-pulse sample minus the 61 ns of on-ramp above the valley, against the target valley (no eq. 7, no `dv` noise: ±0.05 A instead of ±0.5 A); `z_v,f` the same sample's voltage minus `V_ref`, less `ESR (i_s − I_settled)`. The thread takes the full 2×2 Newton step on `[z_i,f; z_v,f]` (`buck_learn_gamma`, the Jacobian with the fall slope `(V_ref + r i_2)/L`, μ 0.25, [0.5, 2], 0.25 per pulse); a peak- or `TON_MAX`-clamped pulse cannot move its charge, so `Toff` alone takes `μ z_i,f / m2`.
- **Equilibrium correction from the settled load.** `e_b = I_settled − I_eq`, the low-passed eq. 7 estimate when the transition ends (±0.15 A) against the equilibrium the pulse was solved for; `b += 0.5 e_b`, |b| ≤ 3 A. On a load that keeps slewing after the pulse, b learns the part the trigger did not see (simulation: +1.0 A for a 20 µs slew).
- **Validity of what is learned.** Clips at ±2 A / ±40 counts as before, and SKIP bounds (`BUCK_OPT_ZI_SKIP_A` 6, `BUCK_OPT_ZV_SKIP_COUNTS` 200): a residual beyond them, or a trigger on a droop beyond 200 counts, is a corrupted sample and that pulse teaches nothing (`flags` in the log). With the bench's zero samples the old rule ran both learners to their bounds; now such a record is dropped.
- **ESR in the solve.** The droop the pulse refills is the ADC error less `ESR (i_s − I_hat)`: during a droop the inductor lags the load, so the sample sits *below* the capacitor by that much (24 mV = 30 counts for a 2 A lag at 12 mΩ, more than half the droop of a 3 A step). One multiply in the solve cycle. The in-loop ESR identification is gone (it read 60 to 75 % of the truth and needed the residual window); measure the spike during the pulse on the scope, divide by `I_pk − I_load`, write `g_buck_opt_esr_mohm`.
- **Panel.** Added `g_buck.status.adc_glitch`, `opt_reject_count`, `opt_zv0`, `opt_dv0` (the trigger sample), `opt_i0_ma`, `opt_zvf` (terminal voltage residual, counts), `opt_zib_ma` (equilibrium residual); `opt_zif_ma` is now the measured landing error. Removed `opt_verr`, `opt_zi_ma`, `opt_zv_mv`, `opt_wait_cycles`, `g_buck_opt_esr_est_mohm`, `g_buck.ctl.opt_meas`, `g_buck_sa_ia`. The per-pulse log carries `zv0, dv0, iload_ma, zib_ma, flags`. `tools/live_expressions.txt` is current; the CubeIDE store could not be rewritten (the IDE was open), so add the rows by hand.

**September 2026 update 4: average current mode with the sensed inductor current, and the ISR put on a diet**

The inductor current is now measured: a 1 mΩ shunt with a 40× amplifier on A1 (PA1 = ADC2_IN2, 20.1 mA per count, zero and scale live-tunable as `g_buck.tune.isense_zero` / `isense_gain_q16`). ADC2 converts it on the same HRTIM trigger and at the same instant as the voltage on A0 (independent mode, both asynchronous 56 MHz; ADC1's EOC stays the one interrupt, the ISR reads both data registers). The control is classic **average current mode**: the voltage PI outputs an average-current reference (Q16 A per count, `kp_q16` / `ki_q16`), a current PI turns the current error into the duty (`kpi_q16` / `kii_q16`, Q16 ticks per Q8 A), saturation-tracking anti-windup on both. The one sample per period sits a fixed (SAMPLE − DT) ticks up the on-ramp, so the period's average is the sample plus the ripple correction `(V_in − V_ref)/L · (T_on/2 − (SAMPLE − DT))`: one multiply, and the only place L enters the loop. Power-on gains from a closed-loop sweep (host simulator, PI alone, 1 to 3 A): `kpi` 64000 (250 ticks/A, 84 % of the current loop's dead-beat gain), `kii` 6000, `kp` 1600, `ki` 100: dip 0.73 V / hump 0.80 V, against 0.69 / 0.83 V with the first guess and 0.705 / 0.806 V with the old predictive inner loop; fall back to 800 / 60 on the voltage loop if the bench rings.

What went, all of it model-current machinery that either added ISR cost or never worked on the bench:

- the predictive peak-current inversion (one UDIV per cycle) and the Padé valley/peak recursion with its 7 KB coefficient table in the ISR: the load estimate is the manuscript's eq. 7 on the *measured* average current, `I_load = i_avg − C dv/dt`, low-passed (eqs 20–21), `buck_load_update`, ~10 clocks; the Padé functions stay in the header for the host tests only;
- the reseed-sensitivity learner `s`, the thread's rest-state tracking and the settled-reference sampling: with a measured current the voltage loop's reference is real amperes, so after a pulse it is reseeded to I_eq itself and the current loop to the duty that holds it, `duty_trig + r/V_in · PER · (I_eq − i_avg,trig)` (the fitted r *is* the DC duty-to-current relation);
- the immediate PI re-anchor (`BUCK_OPT_EQ_NOW_Q8`), the ISR-side residual arithmetic, and the solve's model-current inputs: the pulse start current is the measured valley extrapolated two periods with the measured drift, the new load is measured with the mean of two measured period averages, and the ESR correction of the residual window uses the *measured* currents at its two samples (no model valleys).

The every-cycle ISR is 199 static clocks armed (was 240), with no divide, no table and no call; RAM 5.8 KB (was 13). The solve cycle is 266, the post-pulse cycles store only. Closed loop, 114 mΩ plant, dip / hump (PI alone in brackets): 1 to 3 A 0.743 / 0.803 V (0.732 / 0.801); 1 to 6 A 0.677 / 0.822 V (0.640 / 0.809); 20 and 40 µs slewing 1 to 3 A 0.756 / 0.798 and 0.764 / 0.800 V (0.737 / 0.801); 10 mΩ ESR with the ESR set 0.740 / 0.845 V (the maximum is the ESR spike); γ = 1.00 and |b| < 1 A everywhere, no faults, the same with the thread starved to one pass per 60 periods. A plant whose real series resistance is far below the fitted one (`--rl 0.015`) over-delivers until `g_buck_opt_r_off_mohm` is lowered, as before.

**September 2026 update 3: Jacobian timing adaptation (manuscript Sec. V), the post-pulse dip, and the trigger clean-up**

The pulse timing is now adapted from its own measured residual, as in Sec. V of the TPEL manuscript, instead of being tuned by the string of special-purpose learners and trigger gates that had accumulated (all listed as superseded in update 2 below). Three things changed.

- **A real bug: the first period after the pulse ran at the minimum on-time.** In current mode the PULSE-cycle reseed converted the Q16 *ampere* reference as if it were duty ticks, so the first normal period after every pulse was programmed with `DUTY_MIN` (896 ticks). Simulation of the old code, 1 to 3 A: the inductor current collapsed from 3 A to 0 A in that one period and Vout dropped a further 20 mV before the PI recovered; on a 1 to 6 A step the dip is proportionally worse. This is the "dip after the large signal" seen on the bench, and no equilibrium estimate could have removed it. The write cycle now precomputes the post-pulse on-time with the current loop's own inversion (`buck_cm_ton_ticks` at the reseeded peak reference, from the pulse's terminal valley, at V_ref), and the PULSE cycle only stores it (its cold path went from 64 to 41 static clocks; `opt_solve` holds the two bounded UDIVs, one per path, `tools/check_elf.py` updated).
- **Jacobian timing adaptation.** The applied pulse is `t_a = diag(γ_on, γ_off) t*` (manuscript eq. 40): γ_on scales the physical on-time (the rise above the pulse-start current), γ_off the off-time. After each pulse the ISR measures the terminal residual `z_f = [z_i,f; z_v,f]`: `z_v,f` is the first sample after the stretched period (SETTLE), `z_i,f` the pulse's terminal current minus the load measured over the two normal periods that follow (`i_avg − C dv/dt` over the window, state `OPT_MEASURE`). Because that load is measured *after* the pulse, an inaccurate equilibrium estimate at solve time (the slow-slew case on the bench, where the load is still rising when the solve samples it) appears in `z_i,f` and is corrected by the same update, and the pulse's terminal current `term = i_0 + γ_on (I_pk* − i_0) − γ_off x` is what the estimator and the PI are reseeded to, so the adapted gains move the equilibrium the loop restarts from, not only the pulse shape. The thread then takes the manuscript's Newton step (eqs. 43 to 48), `γ ← Π[γ − μ diag(t*)⁻¹ J⁻¹ z_f]`, with the ideal-LC Jacobian `J = [[m1, −m2], [(z_i0 + m1 (Ton + Toff))/C, (z_i0 + m1 Ton − m2 Toff)/C]]` at the applied times, μ = 0.25, projection onto [0.5, 2.0] with at most 0.25 per pulse; a clamped on-time (peak or `TON_MAX`) is not adapted, and with Ton frozen the step is taken in the Toff direction alone on the residual Toff governs (`ΔToff = μ z_i,f / m2`), because the joint step would chase a voltage deficit only Ton can remove. `Tests/test_solve.c`: on an ideal-LC plant with L 20 % off, C 30 % off and the load mis-estimated by 0.6 A the residual is nulled within 5 to 12 pulses; on a peak-clamped pulse only the current residual is nulled and γ_on stays put. Gains: `g_buck_opt_gamma_on_q16`, `g_buck_opt_gamma_off_q16` (Live Expressions, /65536), residual `g_buck.status.opt_verr` (counts) and `opt_zif_ma` (mA).
- **Dual correction: equilibrium as well as timing (second round, from the scope).** With the pulse landing correctly the scope still showed a +50 mV hump starting ~10 µs after the pulse: the PI restarting from a wrong operating point, because the equilibrium the pulse was solved for (the load measured one period after the edge, on a load that is still slewing) is not where the loop has to settle, and the timing gains were being scored against that wrong equilibrium too. The residual is now split between two corrections, each on the component it can explain: an equilibrium error moves the terminal *current* and not the terminal voltage (the pulse still lands on its target), a charge error moves the terminal *voltage*. So `z_v,f` drives the Jacobian step alone (`J⁻¹ [0; z_v,f]`, i.e. Ton and Toff move together along the direction that keeps the terminal current; a clamped pulse is not adapted in time at all), and `z_i,f` drives the **equilibrium correction** `b ← b − μ_b z_i,f` (μ_b 0.5, |b| ≤ 3 A, `g_buck_opt_ieq_q20`): the next solve targets `I_hat + b`, so the pulse lands on the load as it is rather than as it was estimated, and the Jacobian's `z_i0` is right. The same `z_i,f` also **re-anchors the PI at once**: in the MEASURE cycle its reference is moved by the reference-equivalent of `−0.75 z_i,f` (`s z_i,f` in current mode, `BUCK_OPT_EQ_NOW_Q8`), so the loop restarts from the measured operating point instead of integrating the mismatch away over the next 30 µs. The residual window is now the *first* PI-controlled period only (`BUCK_OPT_MEASURE_PERIODS` 1): that period's on-time is the reseed alone, the PI has not acted yet, so its `C dv/dt` is the cleanest measure of the reseed's current against the true load (one ADC count is 0.12 A there; the learners average it). `Tests/test_solve.c`: matched plant leaves γ = 1.00 and b = 0.00; a 0.6 A load bias is found by b (+0.60 A) with γ untouched; L/C mismatch is absorbed by γ with b small; a peak-clamped pulse has only its current residual nulled. Closed loop, 9 alternating steps (dip / hump): 1 to 6 A on the 15 mΩ plant, which drifted before, now holds 0.68 / 0.835 V step after step (PI alone 0.663 / 0.889 V); 1 to 3 A cases settle at 0.74 / 0.815 to 0.82 V as before; the very first step is somewhat worse where the model's reference scale `s` is far from its initial 1.0 (the re-anchor uses `s` before it has been learned; from the second step on it is right). Every-cycle path unchanged at 240 clocks; the MEASURE cycle does its compare write first and the correction after it.
- **Third round, from the live panel: the fall slope and the terminal state.** After the dual correction was flashed the panel showed every learner at a bound (γ_on = γ_off = 2.0, `s` 0.05, the solve targeting 6.5 A for a 3 A load, `opt_zif_ma` −2341, `opt_toff` 5.6 µs) and the scope a +80 mV spike then a dip after each pulse: the pulse swung the inductor far above and then far below the load. The simulator, given a load that slews like the bench's (`--slew`), reproduced the saturating equilibrium correction and pointed at one physical error in the solve: the off-time was computed with the ideal fall slope `V_ref/L`, but the real fall is `(V_ref + r i)/L`, 1.7 to 2.4 times steeper at 5 to 10 A with r = 114 mΩ (the on-time inversion had the r-drop all along, the off-time never did). Every pulse therefore fell far below its target, b ran to its bound, the timing step's "terminal-current-preserving" direction was wrong by the same factor, and γ walked to 2.0. The solve now carries the series drop on the fall: `T_off = (x + h) L / (V_ref + r i_2)`, `i_2 = I_eq + (x − h)/2` the average current of the fall, with the charge balance and the terminal current corrected accordingly (one more table root and two more bounded UDIVs; solve cycle 284 static clocks, no deadline in that cycle: confirm on the board with `g_buck_opt_solve_cycles` of a `DIAGNOSTICS=1` build). Because `BUCK_R_MOHM` is a DC fit that may include losses that are not in the fall (dead-time conduction, input sag), the fall's resistance is a live tunable, `g_buck_opt_r_off_mohm` (default `BUCK_R_MOHM`): with γ = 1 and b = 0 a pulse that lands *above* the load says it is too high, one that lands below says too low.
- **Terminal state = periodic steady state.** A second sample-phase error was found with the ESR runs: the closed form landed the *instantaneous* current on I_eq at the period start, but in periodic steady state the current at a period start is the valley `I_eq − h`, `h = ripple/2` (2.45 A here). So the first sample after the pulse sat 2.45 A higher on the ripple than every steady-state sample, any ESR turned that into a fixed error of `ESR · 2.45 A · C/T` in the measured load (1.9 A at 5 mΩ, which the equilibrium learner integrated), and every pulse over-delivered `h T` of charge in its first period. The pulse now ends at `(I_eq − h, V_ref)`: the charge balance gains `(V_in − V_ref) h²/(V_ref + r i_2)`, the fall extends by h, the first normal period is an ordinary one (its on-time is the plain inversion from that valley to the reseeded peak reference), the estimator is reseeded at the valley, and the residual window is phase-consistent. **September 2026 update 2: the Ton/Toff solve moved into the ISR (one square root; pulse three periods after the trigger sample)**

*The learners and trigger gates described in this section (gain k, arming counter, recovery test, the reseed learner's gates and anchors) are superseded by update 3 above; the ISR pipeline and the closed form are unchanged.*

Bench symptom (2 A step, current mode, Kp 800 / Ki 60): the trigger fired within a few µs of the load edge, but the D4 pulse appeared ~100 µs later, when the LC ring had already recovered the dip. Live Expressions showed why: `opt_wait_cycles = 51`, i.e. the request sat in OPT_WAIT for 85 µs. With the armed ISR at ~244 of 280 clocks the main loop gets 15 to 35 clocks per period, and the thread's float solve (`buck_optimal_onoff` plus the peak limit, gain, clamps and unit conversions, ~600 instructions from flash) needs ~50 periods of that. No tuning of the trigger can fix a solve that arrives after the recovery.

The solve now runs **inside the ISR**. Measured on the NUCLEO (ST-LINK live reads of a `DIAGNOSTICS=1` build, pulses forced with the power stage off by stepping the setpoint): the ISR is entered 4288 to 4544 HRTIM ticks (134 to 142 clocks) into the period (CMP3 trigger at 600 ticks, ADC trigger resync + 12.5-cycle conversion at 56 MHz + EOC resync + exception entry + the two ADC register reads), so only ~120 clocks remain before the preload write deadline at 8448 ticks (264 clocks). A solve (172 clocks on silicon, incl. two valley predictions) cannot finish inside that window, so the pulse is pipelined over two cold cycles:

- **Trigger cycle (period n).** The every-cycle path captures the state and clears the hot-path flag `control.running` for the next cycle. No new compare on the hot path: the next ISR takes the *existing* cold branch, which now dispatches on `opt_state` to `opt_solve` (a `noinline, cold` CCM helper) instead of `control_transition`.
- **Solve cycle (n+1).** No HRTIM write, no deadline. The pulse will start with period n+3, so the solve is done for the state at that rollover: the valley two periods ahead with the frozen duty (the preloaded CMP1 keeps this duty for n+1 and n+2; `buck_est_predict_iv` twice) and the droop those two periods add, `(I_new - i_avg) 2 T / C` (`g_buck.so.dq_q16`). Then the closed form (below), one `UDIV` in the on-time inversion, results stored in `g_buck.opt` (`ton_ticks`, `toff_ticks`, `ton_sat`, `ipk_q16`, `term_q20`). `running` stays clear.
- **Write cycle (n+2).** `PER` then `CMP1` first thing, measured at 4864 to 6336 ticks (152 to 198 clocks; 66 to 112 clocks before the deadline), D4 high, `opt_state = PULSE`, `running` set: the hot path resumes next cycle. `opt_wait_cycles` reads 2, `opt_write_phase` the tick count of that write.
- **PULSE (n+3) / SETTLE (n+4)** as before; the estimator is reseeded to the solve's terminal current `I_new + x_app (1 - 1/k)` and the PI to `I_new + ripple/2` (computed in the PULSE cycle, `buck_opt_reseed_i`).

Trigger sample to pulse start: three switching periods (5 µs) instead of ~53. Closed-loop simulation of the real code: pulse applied 5.7 µs after a 1 to 6 A step (was ~90 µs). The every-cycle ISR is unchanged at 244 clocks (static count, armed, current mode); the solve cycle is ~245 clocks in the release build (it must only end before the next conversion, not before the deadline), the write cycle ~80, PULSE ~170.

- **Closed form.** Ideal-LC charge balance for a step-up: with `a = i_0 - I_new` (< 0, `i_0` the valley at the pulse start), `dV = V_ref - v_out` (> 0), `m1 = (V_in - V_ref)/L`, `m2 = V_ref/L`, the single ON-OFF pulse that lands on `(z_v, z_i) = (0, 0)` peaks at `I_new + x` with `x^2 = (V_ref/V_in) [2 C (V_in - V_ref)/L dV + a^2]`, `T_on = (x - a)/m1`, `T_off = x/m2` (ON triangle `(x^2 - a^2)/(2 m1)` + OFF triangle `x^2/(2 m2)` = `C dV`). One square root, everything else a multiply. `T_on` is taken from the **same trapezoidal inversion the current loop uses** (`buck_cm_ton_raw`, one bounded UDIV), so the pulse peak lands where the estimator predicts it; the series-r terms of the second-order Pade solve (kept in `buck_optimal_onoff` as the host reference) and the real plant's differences are what the learned gain `k` absorbs, as before: `x_app = k x` (re-capped at `BUCK_OPT_IPK_MAX_A`, `ton_sat`), `T_off = x_app L/V_ref` so the current always returns to `I_new`: k changes the charge, never the terminal current. (The inherited `T_off/k` rule left the current `x_app (1/k − 1)` below the load for k < 1: on the bench, once the k learner had shrunk k, an 80 mV dip right after the pulse followed by a 100 mV overshoot as the reseeded loop slammed the current back up.) `Tests/test_solve.c`: the closed form returns the ideal LC state to (0, 0) to 1e-17; the integer ISR version matches the double form within 7 ticks of Ton, 15 of Toff and 13 mA of peak over 128k points including every clamp, `k`, the terminal current and the stretched-period floor.
- **Integer, ISR-safe.** Currents in Q8 A inside the solve, `dV` clamped to 2047 counts, `V_ref/V_in` as a Q32 high-word multiply (UMULL), the root by `buck_isqrt32`: a 192-entry normalised table (`sqrt(i 2^24)` and slope, i = 64..255, one word each, 768 B SRAM filled at start-up) with `CLZ` normalisation and linear interpolation, ~18 clocks, within 1 LSB of `floor(sqrt)` over 2 million random 32-bit values. **Predictive peak-current mode (`BUCK_CURRENT_MODE`, default 1)**

The inner loop is a model-based peak-current-mode control that needs no current sensor and no HRTIM change. The Pade [1/1] current update in the estimator is exactly the trapezoidal integration of `L di/dt = V_L - r i` over the on-time, `i_pk = i_v + (T_on/L)(V_L - r (i_v + i_pk)/2)`, so its inverse is closed-form: `T_on = L (i_pk_ref - i_v_next) / (V_L - r (i_v_next + i_pk_ref)/2)` ([Inc/buck_cm.h](Inc/buck_cm.h)). Each cycle the ISR runs the estimator's prediction half before the compare write (Pade coefficients from the table, peak, next valley: ~20 clocks), converts the voltage PI's peak-current reference into the on-time of the **next** period with one 32-bit `UDIV` (bounded 2 to 12 clocks), clamps it to the PWM range and writes CMP1; the rest of the estimator (cycle average, load estimate, low-pass) runs after the write. Sample in period n, predict the valley of n+1, program n+1: predictive current-programmed control (Chen, Prodić, Erickson, Maksimović, TPEL 2003). Pinning the peak gives the classic valley recursion `δi_v(n+1) = -(m2/m1) δi_v(n)`, stable for D < 0.5, which the 50 % duty ceiling guarantees; no slope compensation at D ≈ 0.2.

- The voltage PI now outputs a peak-current reference in Q16 A per ADC count; `g_buck_kp_q16` / `g_buck_ki_q16` keep their names but change units and defaults. The paper design was `BUCK_CM_KP_Q16` 2140 (≈ 0.033 A/count, ~20 kHz crossover) / `BUCK_CM_KI_Q16` 90 (PI zero near 4 kHz); it rang at the 16 kHz LC resonance on the bench, and the defaults are now the bench-tuned **800 / 60** (2026-09-24, 2 A step: crossover ~7.5 kHz). Clamped to [0.5 A, `BUCK_OPT_IPK_MAX_A`] with the same saturation-tracking anti-windup.
- The time-optimal pulse's post-pulse reseed sets the integrator to the steady peak reference of the new load, `I_load + ripple/2`, and reseeds the estimator's valley to the solution's terminal current.
- The current is the estimator's model, not a measurement: an error in `BUCK_R_MOHM` shifts the DC current estimate (absorbed by the voltage loop); an error in `BUCK_L_H` scales every on-time. There is no protection against a shorted output or a saturating inductor.
- Host test `Tests/test_cm.c`: the inversion reproduces the model's peak to 3 mA (one tick of ramp) over 3129 operating points, and a closed inner loop pins a 4 A reference within 8 cycles. Closed-loop simulation, 1 to 6 A step: minimum 0.853 V and ~15 µs recovery with the optimal pulse, 0.860 V without it (voltage mode: 0.634 V); 1 to 3 A: 0.938 V; no faults, with ADC noise and 5 mΩ ESR. The optimal pulse now adds little at these step sizes; the next step for a faster response is load-current feedforward into the peak reference (the estimator's `iload_raw` reacts within one cycle).
- `BUCK_CURRENT_MODE=0` restores the voltage-mode duty loop (`-DBUCK_CURRENT_MODE=0`); `tools/check_elf.py` allows exactly one divide in the ISR.
- **Budget.** Static estimate of the every-cycle ISR (±10 to 15 %, incl. 22 clocks of exception entry/exit, period 280): current mode 210 with the optimal trigger disarmed, 244 armed (bench 2026-09-24: armed in current mode runs without fault 5); voltage mode 161 / 193. The trim that got here: one object `g_buck` for everything the ISR touches (one base address instead of five literal-pool loads), the trigger's current signal taken from the two valleys the prediction already holds (no cycle-average bookkeeping), soft-start masked through the cooldown instead of a second flag, the run command polled by the thread instead of every ISR cycle, no redundant EOC test, one v_out conversion shared by prediction and inversion. Current mode still boots with the optimal response **disarmed** (`BUCK_OPTIMAL_ARM_AT_BOOT`, default `AUTO_START && !CURRENT_MODE`) until the armed path has been measured on the bench: arm it with `g_buck.tune.optimal_en = 1`, read `g_buck_isr_cycles_max` from a `DIAGNOSTICS=1` build (add 22 for entry/exit), and if that stays below ~270 set `BUCK_OPTIMAL_ARM_AT_BOOT` to `BUCK_AUTO_START`. The write-phase instrumentation (`BUCK_DIAG_WRITE_PHASE`) is off in current mode so the diagnostics build itself fits.
- **Live Expressions.** Everything the ISR touches is one object: `g_buck.tune.{kp_q16, ki_q16, setpoint_adc, command, optimal_en}`, `g_buck.status.*`, `g_buck.opt.*`, `g_buck.ctl.*` (private state, readable). The old global names still work in the source through macros, but not in the debugger: `g_buck_tune`/`g_buck_status` are not symbols, so Live Expressions must use `g_buck.tune.*` / `g_buck.status.*`. The working list is kept in `tools/live_expressions.txt`; CubeIDE reads its copy (`.metadata/.plugins/com.st.stm32cube.ide.mcu.livewatch/saved_expr.dat`) only when the view is created and overwrites it when the view or the IDE closes, so restore it with CubeIDE closed: `cp tools/live_expressions.txt ../.metadata/.plugins/com.st.stm32cube.ide.mcu.livewatch/saved_expr.dat`. A STOP (`g_buck.tune.command = 0`) is now carried out by the thread within one main-loop iteration (`buck_command_service`); the running ISR no longer polls the command word.

**Configured hardware and electrical values**

| Function | Board pin | MCU function |
|---|---|---|
| High-side driver | D7 / PA8 | AF13, HRTIM1_CHA1 |
| Low-side driver | D8 / PA9 | AF13, HRTIM1_CHA2 |
| Voltage feedback | A0 / PA0 | ADC1_IN1, analog mode |
| Optional timing pulse | D4 / PB5 | GPIO, only with `BUCK_SCOPE_PIN=1` |

Both driver inputs are assumed active-high. VDDA/VREF+ is assumed 3.3 V. No internal op-amp or extra gain is enabled: A0 must already carry the complete supplied feedback transfer, `(2.2/12.2)*(1+46.4/36) = 0.412750455 V/V`. The target is 512 ADC counts, corresponding to about 0.9994 V with ideal 3.3 V reference. One ADC count is about 1.952 mV at the converter output. Measure reference voltage and feedback gain for accurate absolute regulation.

The stage values are Vin=6 V, Vout=1 V, L=330 nH, Cout=260 µF. Ideal high-side on-time is 277.8 ns (16.67%). The internal compare ordinarily needs approximately 1765/8960 (19.70%) to account for the rising-edge dead time, before driver/FET losses and diode-conduction effects. The PI settles the actual duty; this estimate is not imposed as a fixed duty or feedforward term.

**Clock and timing choices**

| Setting | Value |
|---|---|
| CPU, AHB, APB1, APB2, HRTIM base | 168 MHz, Range 1 boost |
| PLL | HSI16 /4 ×84; R /2 to CPU; P /6 to ADC |
| ADC1 kernel | 56 MHz asynchronous, prescaler /1 |
| HRTIM prescaler / period / repetition | ×32 / 8960 / 0 |
| PWM period / CPU budget | 1.666667 µs / 280 CPU clocks |
| HRTIM fine tick | 186.012 ps nominal |
| Dead time, both transitions | 68 × 1/(168 MHz ×8) = 50.595 ns |
| Default ADC trigger | Timer A CMP3=4352, at 809.524 ns into the period |
| Trigger to next preload activation | 144 CPU clocks = 857.143 ns |
| Latest permitted pre-write counter read | CNT <8448, retaining a 16-clock guard |
| Compare limits | 896..3584 (10%..40% raw compare duty) |
| Minimum high-side gate pulse | approximately 116.07 ns at the 10% command |

168 MHz is 1.18% below the part's 170 MHz limit and gives an integer, constant 600 kHz period. At 170 MHz a fixed integer ×32 period cannot give exactly 600 kHz. These rates are **nominal**: HSI oscillator error appears in the actual PWM frequency. For crystal accuracy, verify the board's HSE solder-bridge routing and select `BUCK_USE_HSE=1`; the configured alternative is a 24 MHz crystal with PLL M=6. For an externally driven clock, also configure `BUCK_HSE_BYPASS` and `BUCK_HSE_HZ`. There is no silent fallback if HSE fails.

Distinguish three latencies: (1) sample/hold to ADC result, (2) result to the CPU compare write, and (3) that write to the active PWM compare. A preload write does not instantly change the waveform. Here, activation is always the immediately following period boundary if the deadline is met. The first duty-dependent trailing edge follows that boundary by the new compare value (approximately another 328 ns at nominal duty). The ADC aperture follows the trigger through hardware synchronization; the 857 ns figure is trigger-to-activation, not a measured aperture-to-edge time.

**Why this path is short**

ADC1 is reserved for one 12-bit regular channel, hardware-triggered by HRTIM ADCTRG1 (`EXTSEL=21`, rising edge). `ADSTART` is armed once. Bulb mode keeps the input connected between conversions, addresses the single-channel multiplexer erratum, and provides a long acquisition interval without putting all that interval after the trigger. First-conversion sampling is 2.5 ADC clocks; the first eight conversions are discarded with gates disabled. Successive approximation itself takes 12.5 ADC clocks, approximately 223 ns at 56 MHz; synchronization and the first-sample acquisition add latency. Budget conservatively and measure the actual trigger-to-EOC delay. No oversampling or averaging adds cycles of delay.

A second ADC would not shorten the successive approximation of this voltage sample. Injected conversion offers no arbitration benefit when this ADC is dedicated, and it is incompatible with bulb mode. DMA would add an intermediary transfer/notification for a single value that the CPU immediately needs. The ISR therefore reads ADC1->DR directly, clearing EOC. OVRMOD disables the ADC data FIFO; any overrun faults instead of using a lost sample.

The handler and its literal pool execute in CCM at 0x10000000. The vector table is copied into aligned SRAM; hot state and exception stack use SRAM1/SRAM2. The normal SRAM region is 96 KiB, avoiding the 32 KiB CCM alias at 0x20018000. `buck_init()` copies the CCM load image before interrupts are enabled. Both Flash and RAM linker configurations support this placement.

The PI uses signed 32-bit Q16 arithmetic: `p=Kp*e`, `u=clamp(i+Ki*e+p)`, `i=u-p`. The last step provides saturation-tracking anti-windup. Fractional integrator bits are retained. Compile-time bounds reject gains that could overflow for a full-scale error reversal. GCC emits one MUL and one MLA, with no floating point, division, 64-bit arithmetic, or normal-path calls. Unit conversions and coefficient scaling are precomputed. A 10 ms reference ramp, telemetry stores and optional diagnostics follow the compare write. SysTick and timer interrupts are disabled; ADC IRQ has highest configurable priority. Sleep-on-exit avoids repeated foreground execution.

Startup explicitly sets `DBGMCU_CR.DBG_SLEEP` to keep the debug AHB clock available during sleep-on-exit/WFI, and clears inherited deep-sleep state. Faults force both gates low and then remain awake so `g_buck_status.fault` can be inspected. These changes add no instructions to the normal PI path. The debug clock consumes additional power during sleep. `clock_init()` updates `FLASH_ACR` with a read-modify-write because bit 18, `DBG_SWEN` (reset value 1), gates the SWD debug port on the G4: a plain assignment of latency/cache bits clears it and ST-LINK reports "Target is not responding" a few microseconds after reset release, independent of sleep settings, until the next reset (verified on the NUCLEO-G474RE). If that message reappears, connect under reset (already selected in the project launch configuration) and check for any new whole-register write to `FLASH_ACR`; then inspect the first latched fault and check target supply/reset/SWD integrity. Keep the power stage disabled while reconnecting or using breakpoints.

Timer A uses edge-aligned continuous counting, positive dead time, equal comparison, and a period/repetition preload transfer every cycle. CHA2 is generated by the dead-time unit from CHA1; it is not separately inverted, and push-pull mode is disabled. The ISR never forces a software update. Immediate compare writes can miss an already-passed edge, and the G474 has an additional greater-than PWM update erratum; neither mode is used here. Dead-time values and signs are locked until peripheral reset.

**PI tuning and limits**

The initial coefficients are deliberately provisional: Kp approximately 0.02 duty/V and Ki approximately 104.7 duty/(V·s), represented by `BUCK_KP_Q16=22924` and `BUCK_KI_Q16=200`. They provide a low-bandwidth starting point; they are not validated for the actual converter. With feedback slope S=512.310868 counts/V, compute:

```
Kp_q16 = round(Kp_duty_per_V * 8960 / S * 65536)
Ki_q16 = round(Ki_duty_per_V_per_s / 600000 * 8960 / S * 65536)
```

The ideal LC resonance is about 17.18 kHz. Load resistance, capacitor ESR, inductor DCR, driver delay and the feedback amplifier response are still needed for final compensation. A PI controller alone cannot be assumed stable at light/no load with a lightly damped LC filter. The ideal zero-ESR/DCR averaged model gives the necessary Routh condition `Vin*Ki < (1+Vin*Kp)/(Rload*Cout)`; it is not a complete sampled-data stability test. Verify loop gain/phase and load steps on the real stage before raising bandwidth. Sampling at 600 kHz does not imply a 600 kHz closed-loop bandwidth.

The soft-start is a voltage-reference ramp, not a current limit; the duty command starts at its 10% lower limit. This implementation is forced synchronous operation and can conduct reverse inductor current. A0 no longer inhibits startup at any valid ADC level, including a prebiased output, and there is no A0-based overvoltage trip. The supplied 330 nH stage has roughly 4.2 A peak-to-peak ideal inductor ripple at 6 V ->1 V and 600 kHz; account for that in hardware current protection. A0 is voltage only, so no current comparator/fault routing has been invented. Driver EN/FAULT and hardware current protection remain external design responsibilities.

Every armed duty command is clamped to 10–40% (`CMP1=896..3584`, `PER=8960`) using the existing fixed-point PI saturation and tracking anti-windup. Initialization and arming use the same 10% lower bound. The percentages describe the compare command before dead time; with 50.595 ns rising-edge dead time, the high-side pin is nominally high for approximately 6.96–36.96% of the period. Duty limits bound the actuator command but cannot detect or guarantee protection against output overvoltage, overcurrent, or incorrect A0 feedback. Hardware minimum pulse and dead-time bounds are compile-time checked. The 10% minimum duty does not allow regulation arbitrarily close to zero; `g_buck_command=0` still disables both gates and reports zero active duty. ADC overrun, update-deadline, initialization, and CPU faults still shut down the outputs. Former A0 fault codes 6 and 7 are retired; remaining fault numbers are unchanged. The old `BUCK_IGNORE_A0_PROTECTION` / `IGNORE_A0` build switch has been removed because both threshold checks are now absent in every build. A0 remains the cycle-by-cycle PI feedback input. Sampling and arming occur in the low-side interval across the configured duty range. Inspect A0 switching noise and amplifier settling; a delayed/noisy analog feedback path cannot be repaired by making the ISR faster.

**Build and bench verification**

Refresh the existing project in STM32CubeIDE and build Debug or Release. Both are configured for `-O3`, CMSIS includes, `STM32G474xx`, and `-fno-builtin`; do not run the cycle loop at `-O0`. This is a standalone register-level project with no .ioc/HAL dependency. Vendored CMSIS files retain upstream licenses; provenance is in `Drivers/CMSIS/PROVENANCE.md`.

The root Makefile also builds using the installed CubeIDE GCC, or `TOOLCHAIN=/path/to/bin`:

```
make -j4 check
make -j4 BUILD=build-diagnostics DIAGNOSTICS=1 SCOPE_PIN=1 SAMPLE_LEAD=152 check
make -j4 BUILD=build-hse USE_HSE=1 check
make -j4 BUILD=build-ram LDSCRIPT=STM32G474RETX_RAM.ld check
```

Build outputs are ELF/HEX/BIN, map and disassembly under the selected build directory. Command-line build option changes invalidate existing objects. Gate autostart remains off unless explicitly set in configuration (Make: `AUTO_START=1`).

For the optional target-code tests, install `unicorn` and `pyelftools` in a Python virtual environment, then run `python Tests/test_target.py build/Buck_Voltage_Mode.elf`. These tests mock peripherals and do **not** model STM32 bus timing or prove electrical behavior.

1. With the power stage unpowered or its driver disabled, check pin polarity, output inactivity at boot, then arm and scope both gate outputs: 600 kHz, both dead-time gaps, and minimum/maximum pulse widths. Verify the board button is not jumpered to A0 (SB21).
2. Build diagnostics with the longer 152-clock lead first. D4 rises near ISR entry and falls after the compare write/barrier. Warm-up, stop and arm pulses represent different code paths; use steady running pulses for timing. D4 excludes hardware exception entry and ADC conversion delay. Diagnostic builds add bus traffic and instructions. With the new 40% ceiling, the former 176-clock lead would put the trigger inside the possible high-side pulse; it is rejected by the sampling-phase assertion. The 152-clock example places CMP3 at 4096, after the maximum compare plus dead time. Verify analog settling and the full ISR deadline on hardware.
3. `g_buck_status.adc_irq_interval_max` should be about 280 CPU clocks plus synchronization jitter in uninterrupted steady operation. `write_phase_max` records the latest post-write timer count. `isr_cycles_max` measures instrumented C-body time up to its final timing read; it excludes exception entry/return and a few trailing diagnostic instructions. Diagnostic `cycles` counts ADC IRQ entries. Counters wrap; maximum values are reset by MCU reset. `adc_raw` and `duty_ticks` are available in the normal build too.
4. Check timing at both saturation limits and during the entire startup ramp. Reduce `BUCK_SAMPLE_LEAD_CYCLES` (Make: `SAMPLE_LEAD`) in small steps, retaining margin for ADC synchronization, APB access, measurement overhead and interrupt return before the next sample. Normal default is 144 clocks; diagnostic example is 152. A late pre-write phase or rollover during the write latches `BUCK_FAULT_DEADLINE`. Never infer elapsed nanoseconds from instruction count alone.
5. Rebuild without diagnostics for lowest overhead, then validate at low input power/current limit and assess compensation with actual load/ESR. Do not halt or single-step the CPU with an energized power stage: peripherals may continue and a frozen timer can also hold a gate active. Disable the driver before breakpoints. Avoid adding background DMA, interrupt masking, other ADC conversions, or higher-priority work without remeasuring the deadline.

**Verification record**

The initial implementation passed Arm GNU GCC 14.3 and STM32CubeIDE builds, host PI tests, and compiled Thumb-code tests in normal, diagnostic, HSE, and RAM configurations. These are software checks; the recorded board startup/debug verification predates the 10–40% revision.

For the 10–40% revision, the regression suite checks two million PI cases against a wide-integer oracle under undefined-behavior sanitization, saturation recovery, fractional integration, reference ramp and pulse bounds. Compiled Thumb-code tests cover all 4096 valid A0 codes and the former trip thresholds, arming at full-scale A0, exactly one duty write per armed sample, both saturation rails and recovery, disarming, and the retained ADC-overrun/deadline shutdowns. ELF checks verify CCM placement and absence of FP/divide/HAL/normal-path calls. See the revision verification log accompanying the firmware for executed builds and outcomes. Peripheral emulation is not cycle accurate and does not verify analog settling, waveforms, or closed-loop stability.
